# 연결 설정 개선판

- 한국투자 App Key / App Secret은 등록 후 입력칸에 다시 표시하지 않습니다. 두 키의 등록 상태를 별도로 표시합니다.
- ‘한국투자 키만 저장’은 Gemini 모델이나 요금 설정이 미완료여도 저장합니다. 빈 입력칸은 기존 값을 유지합니다.
- ‘저장된 한국투자 키로 인증 확인’은 실전투자 API 서버의 인증 토큰 발급을 확인합니다. 토큰과 키를 화면에 반환하지 않습니다. 시세 수신 및 이용 자격 확인과 실제 주문 실행을 뜻하지 않습니다.
- 키를 변경하면 이전 인증 토큰과 시세 캐시를 무효화합니다.
- Gemini는 키 저장 → 모델 목록 불러오기 → 조회된 모델 선택 → 설정 저장 순서입니다. 요금은 해당 프로젝트의 실제 단가를 입력해야 합니다. 무료 자격을 확인한 경우에만 0원을 입력합니다.

## 기존 사용자의 업데이트

실행 중인 패턴랩 서버 창을 종료합니다. 이번 ZIP을 별도 폴더에 압축 해제한 후, 그 안의 `app.html`, `server.py`, `connectors.py`, `bootstrap.py`, `start_windows.bat` 다섯 파일을 **기존 패턴랩 폴더**에 덮어씁니다. 기존 `data` 폴더는 변경하지 않습니다. 같은 Windows 사용자 계정에서 `start_windows.bat`을 실행하고 브라우저에서 Ctrl+F5로 새로고침합니다.

별도 새 폴더에서 실행하면 기존 폴더의 키와 원장은 자동으로 불러오지 않습니다. API 키는 백업 ZIP에도 포함되지 않습니다.

## 검증 범위

자동 테스트 66개 통과. 임시 서버와 가짜 공급원으로 한국투자 키 별도 저장, 키 마스킹, 인증 확인 UI, 모델 선택과 기존 전체 브라우저 흐름을 검증했습니다. 실제 한국투자 인증은 사용자의 PC에서 확인 버튼으로 수행해야 합니다. 개발 환경에서는 사용자 한국투자 키로 인증하지 않았습니다. Windows 실기 저장 검증 및 전체 Gemini 회의의 공급자 503 보류는 기존 점검표와 같습니다.


## 시세 갱신 오류 개선

공급원 등록은 설정 저장이며 실제 다운로드 성공이 아닙니다. 저장된 종목·가격 기준·이용 조건을 화면에 복원합니다. 화면 설정을 바꿨다면 다시 등록한 후 갱신해야 합니다. 한국투자 일봉 조회에서 발생한 오류는 일반 실패 문구 대신 인증 확인 및 권한·호출 제한 확인 순서를 표시하며, 응답에 있는 인식 가능한 HTTP/API 오류 코드만 노출합니다. 공급자가 원인을 주지 않았다면 구체적인 코드가 없을 수 있습니다. API 키와 원본 응답은 오류에 포함하지 않습니다.

개발 검증에서는 공급자 실패를 가짜 응답으로 재현했습니다. 사용자의 실제 시세 갱신 실패 원인은 이 화면만으로 확정하지 않았습니다.


## Stooq 자동 다운로드 제한 (2026-10-30)

개발 환경의 실제 SOXL 조회에서 HTTP 200이지만 `text/html` 브라우저 JavaScript 확인 화면을 반환하는 것을 확인했습니다. 사용자 노트북에서도 같은 원인인지는 기존의 일반 오류만으로 확정하지 않습니다. 수정판은 브라우저 확인·일반 HTML·빈 데이터·필수 열 누락·잘못된 가격·HTTP 403/429·네트워크 실패를 구분합니다. 제한을 우회하거나 다른 공급원으로 몰래 대체하지 않습니다. HTML을 시세로 저장하지 않으며, 한국투자 데이터와 키는 그대로 유지합니다. 정상적인 외부 CSV를 확보하면 CSV 가져오기로 등록할 수 있습니다. 두 번째 공급원 확보 전에는 두 공급원 검증을 통과했다고 표시하지 않습니다.

개발 환경에서 실제 SOXL Yahoo 응답을 파싱해 최근 종료 거래일 2026-10-29까지 251개 일봉, 분할 이벤트 0개를 확인했습니다. 사용자 DB에 시험 데이터를 넣지 않았습니다. 한국투자와의 실제 가격 비교 및 학교망의 Yahoo 접속은 아직 미검증입니다. 조회 날짜는 뉴욕 시간으로 변환하고 미완료 당일봉을 제외합니다. 원본 JSON을 해시와 함께 보존하고 분할 이벤트도 별도로 기록합니다. 자동 테스트 88개와 브라우저의 Yahoo 선택·가격 기준 고정·시험 수집·목록 반영·연결 중지 흐름을 검사했습니다. 브라우저 시험 응답은 가짜 공급원이며 실제 네트워크 조회 검증과 구분합니다.


## 회의 시작 비활성화 안내 (2026-10-31, 빌드 2026-10-31.1)

회의 실행 버튼 아래에 설정 부족·데이터 미선택·진행 중인 회의·요청 처리 중 상태를 표시합니다. Gemini 공통 모델과 입력/출력 단가 이름은 설정 화면의 이름으로 안내하며, 저장된 키를 다시 등록할 필요는 없습니다. ‘API 연결 설정으로 이동’ 링크는 해당 탭을 바로 엽니다. 실제 사용자 설정은 노트북에 있으므로 사진만으로 어떤 항목이 부족한지는 단정하지 않습니다. 브라우저 시험에서 설정 미완료 시 비활성화·구체적인 안내·설정 탭 이동과 설정 완료 후 버튼 활성화를 검증했습니다.


## Gemini HTTP 400 진단 (2026-10-31, 빌드 2026-10-31.2)

기존 ‘모델·요청 형식을 거부했습니다’ 메시지만으로는 실제 원인을 알 수 없었습니다. 크기를 제한한 Google 오류 응답에서 알려진 키 무효/만료, 지역 제한, thinking 옵션, JSON 스키마, temperature 키워드만 분류합니다. 원본 메시지·세부 metadata·키·프롬프트는 로그/화면에 내보내지 않습니다. 알 수 없는 원인은 HTTP 코드와 모델 ID를 표시하며, 자동 모델/키 변경 또는 자동 재전송은 하지 않습니다.

기존 0회 재심의 회의는 업데이트 후 같은 기록을 선택해 ‘보류 회의 재심’을 한 번 실행하면 새 오류 진단이 기록됩니다. 이전 이벤트는 변경하지 않으며 재심 제한과 비용 예약은 그대로 유지합니다. 이미 재심 한도를 소진했으면 우회하지 말고 로그를 확인합니다. API 키는 다시 입력할 필요가 없지만 Google에서 실제로 폐기/만료된 키라고 확인된 경우에는 해당 역할만 교체해야 합니다. 개발 환경에서 같은 설정과 보고서 스키마의 countTokens 성공을 확인했습니다. 이 검사는 generateContent 성공이나 사용자 노트북 키의 유효성 증명이 아닙니다.


## 회의에서 TTS 모델 차단 (2026-10-31, 빌드 2026-10-31.3)

사용자 재심 로그의 실제 모델이 `gemini-3.8-flash-tts`인 것을 확인했습니다. TTS는 음성 생성 모델이며 회의의 구조화 JSON 보고서에 사용하지 않습니다. 기존 모델 목록은 generateContent 지원만 확인해 음성 전용 모델도 보여주었습니다. 이제 TTS·음성·이미지·라이브·임베딩 전용 모델은 목록에서 제외하고 설정 저장 및 회의 시작 전에도 차단합니다. 지원되는 일반 텍스트 모델로 사용자가 명시적으로 바꿔야 하며 자동 교체하지 않습니다.

① API 연결 설정에서 조회된 일반 텍스트 모델(예: 해당 키에서 실제 제공하는 `gemini-3.8-flash`)을 공통 모델로 선택합니다. 각 역할의 ‘프로젝트·모델·실제 한도’를 열어 개별 모델이 TTS인지 확인하고, 공통 모델을 쓸 경우 개별 모델을 비운 뒤 저장합니다. 저장된 키와 단가는 유지합니다. 이후 실패 기록을 선택해 남은 재심 범위 내에서 한 번 실행합니다. 이 변경은 음성 모델 선택 오류를 해결하지만 실제 전체 12단계 완료를 보장하지 않습니다. 기존 실패 기록은 보존합니다.
